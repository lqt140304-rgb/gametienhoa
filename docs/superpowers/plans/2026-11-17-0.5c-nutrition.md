# 0.5c — Dinh dưỡng: 5 chất, cơ quan cần chất, thiếu thì yếu dần: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Slime có 5 kho dinh dưỡng kiểu slime (Sợi Nhầy, Tinh Vôi, Huyết Thiết, Mỡ Nhờn, Tinh Chất Sống). Mỗi nguồn thức ăn cho một bộ chất khác nhau; mỗi cơ quan cần một chất để **trang bị**; thiếu chất kéo dài thì cơ quan **yếu dần rồi tan**; thiếu chất cũng làm cơ thể suy yếu theo kiểu thật (hồi máu chậm, xương giòn, thiếu máu, lạnh nhanh, giác quan kém).

**Architecture:** Dữ liệu và luật là C# thuần (`NutrientKind`, `FoodProfile`, `NutrientEffects`, `OrganDecay`) để test được. `SurvivalState` giữ 5 kho, hao theo thời gian và theo số cơ quan đang cần chất đó; `OrganHost` chặn trang bị khi thiếu chất và cho cơ quan yếu dần. Các nguồn thức ăn đưa kèm "hồ sơ dinh dưỡng" khi cho ăn. HUD chỉ nổi bật chất đang thiếu; thân slime đổi màu báo thiếu.

**Tech Stack:** Unity 6.6, URP, C#, EditMode tests.

**Spec:** `docs/superpowers/specs/2026-11-17-underroot-survival-slice-design.md` mục 5 (bảng 5 chất) và 6.3.

### Task 1: Chất, hồ sơ thức ăn, hệ số ảnh hưởng (C# thuần)

**Files:** Create `Scripts/Survival/NutrientKind.cs`, `FoodProfile.cs`, `NutrientEffects.cs`; Test `Tests/EditMode/NutrientModelTests.cs`.

**Interfaces:**
- `public enum NutrientKind { Protein = 0, Calcium = 1, Iron = 2, Fat = 3, Vitamin = 4 }` và `public static class NutrientKinds { public const int Count = 5; public static string SlimeName(NutrientKind k); public static string RealName(NutrientKind k); public static Color Color(NutrientKind k); }` (Sợi Nhầy/đạm, Tinh Vôi/canxi, Huyết Thiết/sắt, Mỡ Nhờn/chất béo, Tinh Chất Sống/vitamin; màu: sợi nhầy hồng nhạt, tinh vôi trắng ngà, huyết thiết đỏ, mỡ nhờn vàng, tinh chất sống xanh lục).
- `public readonly struct FoodProfile { public readonly float Protein, Calcium, Iron, Fat, Vitamin; float Of(NutrientKind k); }` — mỗi trường là số điểm chất nhận được **cho mỗi 1 đơn vị calo** ăn vào.
- `public enum FoodKind { Generic, PreyMeat, PredatorMeat, GlowMoss, AmberBud, SporePod, RootDew, EmberBerry }` và `public static class FoodProfiles { public static FoodProfile For(FoodKind kind); public static FoodProfile Carcass(bool rotten); public static readonly FoodProfile Mixed; }` với số (đề xuất): Generic = Mixed (mỗi chất 0,25); PreyMeat (đạm 1,0, sắt 0,4, béo 0,3); PredatorMeat (đạm 1,2, sắt 0,8, béo 0,5, canxi 0,2); GlowMoss (vitamin 1,0); AmberBud (béo 0,8, vitamin 0,3); SporePod (vitamin 0,6, canxi 0,4); RootDew (canxi 1,0, vitamin 0,2); EmberBerry (sắt 0,8, vitamin 0,2). `Carcass(rotten: false)` = PredatorMeat; `Carcass(rotten: true)` = PredatorMeat × 0,3.
- `public static class NutrientEffects` (mọi hàm nhận giá trị kho 0..100, trả hệ số; **bằng 1 khi ≥ 40**, đổi tuyến tính về giá trị biên ở 0): `HealMultiplier(protein)` → 0,4 ở 0; `DamageTakenMultiplier(calcium)` → 1,4; `MaxHealthMultiplier(iron)` → 0,7; `EnergyRegenMultiplier(iron)` → 0,6; `TemperatureDriftMultiplier(fat)` → 1,8; `SenseMultiplier(vitamin)` → 0,6.

### Task 2: Năm kho trong `SurvivalState`

**Files:** Modify `Scripts/Survival/SurvivalConfig.cs`, `Scripts/Survival/SurvivalState.cs`; Test `Tests/EditMode/SurvivalNutrientTests.cs`.

**Interfaces:**

- Trong `Tick` (sau khát, trước máu): mỗi kho hao `(NutrientBaseDecayPerSec + NutrientLoad[k] × NutrientOrganDecayPerSec) × dt`, kẹp ≥ 0. Rồi áp hệ số: hồi máu × `HealMultiplier(protein)`; trần máu hiệu dụng = `MaxHealth × MaxHealthMultiplier(iron)` (máu vượt trần thì cắt xuống, hồi máu kẹp ở trần); hồi năng lượng × `EnergyRegenMultiplier(iron)` (nhân thêm vào các hệ số sẵn có); `TemperatureChangePerSec` × `TemperatureDriftMultiplier(fat)`. `Damage()` công khai (đòn từ ngoài) × `DamageTakenMultiplier(calcium)`; sát thương đói/khát/nhiệt độ qua `ApplyDamage` **không** nhân.
- `Reset()` đặt cả 5 kho = `NutrientStart`. `Revive(health)` đặt sàn mỗi kho ≥ 50 (người được cứu không chết lại vì thiếu chất).
- Mọi hệ số bằng 1 khi kho ≥ 40: hành vi cũ nguyên vẹn.

### Task 3: Cơ quan cần chất, chặn trang bị, yếu dần rồi tan

**Files:** Create `Scripts/Organs/OrganNutrient.cs`, `Scripts/Organs/OrganDecay.cs`; Modify `Scripts/Organs/OrganSO.cs`, `OrganHost.cs`, `OrganInteractor.cs`; Test `Tests/EditMode/OrganNutritionTests.cs`.

**Interfaces:**
- `public enum OrganNutrient { Auto = 0, Protein, Calcium, Iron, Fat, Vitamin }` và `public static class OrganNutrients { public static NutrientKind DefaultFor(OrganSlot slot); }` với `Eyes → Vitamin`, `Legs → Protein`, `Skin → Fat`, `Back → Calcium`.
- `OrganSO`: thêm trường `public OrganNutrient NutrientNeed = OrganNutrient.Auto;` và `public NutrientKind EffectiveNutrient => NutrientNeed == Auto ? DefaultFor(Slot) : (NutrientKind)(NutrientNeed - 1);` (Tooltip: chất cần để trang bị; Auto = theo vị trí gắn).
- `public static class OrganDecay { public static float Step(float decay, float nutrientValue, float equipThreshold, float warnThreshold, float dissolveSeconds, float recoverSeconds, float dt); public static float StrengthFactor(float decay); }`: nếu `nutrientValue < warnThreshold` thì `decay += dt / dissolveSeconds`; nếu `nutrientValue ≥ equipThreshold` thì `decay -= dt / recoverSeconds`; ở giữa giữ nguyên; kẹp 0..1. `StrengthFactor(decay) = 1 - 0.8 × decay`.
- `AttachCheck` thêm giá trị **cuối cùng** `LackNutrient` (không đổi giá trị số của các giá trị cũ). `OrganHost.Check(organ)`: sau các kiểm tra cũ, nếu `stats` có và `!stats.IsRemote` và kho chất `organ.EffectiveNutrient` < `NutrientEquipThreshold` thì trả `LackNutrient`; `TryAttach` trả false với `LackNutrient`. `OrganInteractor` thêm `case AttachCheck.LackNutrient:` trong cả hai `switch` (hộp thoại: "Thiếu {tên slime} ({tên thật}) để mô phỏng cơ quan này. Ăn thêm {nguồn gợi ý}. Có thể hấp thụ (F) để lấy EXP." với `accept` rỗng; nhánh `E`: không làm gì như `default`). Thay thế (`SlotOccupied`) cũng phải kiểm kho chất của cơ quan mới.
- `OrganHost`: mỗi `Entry` có `float Decay`. `Recalculate` ghi `stats.State.NutrientLoad[k]` = số cơ quan có `EffectiveNutrient == k`. `Strength(e)` nhân `OrganDecay.StrengthFactor(e.Decay)`. Trong `Update` (bỏ qua nếu `stats == null || stats.IsRemote`): `e.Decay = OrganDecay.Step(...)`; khi `Decay ≥ 1` thì cơ quan tan: `Detach(slot)` rồi `OrganPickup.Spawn(organ, vị trí dưới chân)` (bản mẫu tạm: nhặt lại phải nuôi từ đầu; ghi chú: bản mẫu thật ở 0.5e); báo `Dissolved` (event mới). Thêm `float GetDecay(OrganSO)` cho HUD/Bảng cơ thể.

- [ ] **Step 1: Test** (tên cố định): `DefaultNutrientBySlot` (4 vị trí); `AutoVersusExplicit` (`EffectiveNutrient` theo `Auto` và theo giá trị gán); `OrganDecayStepsAndRecovers` (kho 10: decay tăng đúng `dt/300`; kho 50: giảm đúng `dt/600`; kho 30: đứng yên; kẹp 0..1); `NeverDissolvesWhileSupplied` (kho ≥ 40 trong 1 giờ mô phỏng: decay luôn 0); `StrengthFactorBounds` (0 → 1; 1 → 0,2); `LackNutrientBlocksOnlyAttach` (`OrganHost` thật trên GameObject + `SurvivalStats`: `Check` trả `LackNutrient` khi kho thấp, `Ok` khi đủ; `AlreadyOwned`/`SlotOccupied` vẫn thắng theo thứ tự nêu trong Interfaces nếu bạn đặt `LackNutrient` sau chúng).
